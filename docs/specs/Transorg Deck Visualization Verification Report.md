# Verification Report: TIQ Marks POC specification set

**Reviewed:** all seven markdown spec files, `TIQ Marks POC Feature Roadmap.xlsx`, `build_roadmap.py`
**Against:** the six process walkthrough notes (phases 1 to 6), the AllianceBernstein process map deck (`Alliance Bernstein Marks Process.pptx`), the 20-question discovery questionnaire (`q.docx`)
**Date:** 8 October 2026
**Method:** every number in the six notes was listed and searched for in all seven documents and the workbook; every derived value was recomputed; step coverage, cross-document ids, workbook integrity and style rules were checked by script (openpyxl, regex) and by reading.

---

## 1. Summary

| Severity | Count |
| --- | ---: |
| Blocker | 0 |
| Major | 9 |
| Minor | 27 |
| **Total** | **36** |

Headline results:

- **Numbers:** every number from the source notes appears correctly and every derived value recomputes (values, deltas, totals, the 11.25 percent Sunrise move, 55 / 16, 16 / 6.2, the 86.2 cross-check). No arithmetic errors. Two synthetic-data dates contradict the source timeline (findings 10 and 11) and one ratio is shown as 3.44x in Agentic AI Spec - Transorg Deck.md where every other document says 3.4x (finding 24).
- **Step coverage:** all 22 quarterly steps and 6 monthly steps are present with the eight-row process table, step names and owners match the deck, loops QA to QE and MA to MC and gates G1 to G3 match. The six monthly steps have **no audit events and no acceptance criteria** (finding 1).
- **Cross-document consistency:** screen ids and agent ids are defined once and used consistently in name and level. Fourteen section cross-references point at the wrong section after a renumbering of Transorg Data Spec.md and Agentic AI Spec - Transorg Deck.md (finding 2). Four tables used in Ingestion Integration Spec - Transorg.md and the workbook do not exist in Transorg Data Spec.md (finding 3). The step-to-screen matrix in Transorg Functional Spec.md Part D disagrees with the screen index in Transorg UI UX Spec.md in six places (finding 12).
- **Workbook:** 112 rows, ids F-001 to F-112 in order, Status validation present, all "Not started", Summary formulas correct and cached values add up (253 days = 243 developer + 10 designer), 16 open items with valid statuses, Arial throughout, no dashes. **Two forward dependencies** (F-027 depends on F-028; F-081 depends on F-083) break the build-order rule (finding 4).
- **Style:** zero em dashes, zero en dashes, zero standalone "AB" in all seven documents and the workbook. All markdown tables have consistent column counts. All mermaid blocks parse (balanced brackets, every edge node defined).
- **Design principles:** no agent or LLM component sets a mark, rating, watchlist flag, approval, send-back, file share or Everest write. Two soft spots: a configurable auto-send of AI-drafted chase emails (finding 15) and the absolute "agents never write to a business entity" statement contradicted by A0 and A4 auto-applied outputs (finding 16).
- **Logic:** the G1 decision model ("Approve" always equals Lincoln's point) makes agenda test 4 unreachable at Q16 and makes a seeded scenario in Transorg Data Spec.md impossible (finding 5). The loan count is 24 in some places and 22 in-scope in others (finding 6).
